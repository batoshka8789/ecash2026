# Передача проекта

Документ для команды, которая принимает код, переключает API на боевой и
запускает сайт на своём сервере.

Всё, что здесь написано, **проверено запуском настоящего контейнера** против
чистой базы данных — не выведено из чтения кода. Что именно проверено,
указано в конце.

Дополнительно: `README.md` — устройство проекта, `.env.example` — полный
список переменных с пояснениями.

---

## 1. Что нужно сделать

1. Получить у своей команды **боевую пару** `ECASH_CLIENT_ID` /
   `ECASH_CLIENT_SECRET`. Dev-пара из документации на проде не работает.
2. Поставить `ECASH_API_BASE_URL` на боевой адрес.
3. Сгенерировать `SESSION_SECRET`: `openssl rand -base64 32`.
4. Указать `DATABASE_URL` (PostgreSQL 17) и `APP_ORIGIN` — в проде
   обязательно `https`, иначе сервер не стартует.
5. Заполнить `ADMIN_PHONES` — иначе раздел `/admin` закрыт для всех.
6. Собрать образ, **передав `NEXT_PUBLIC_*` build-аргументами** (раздел 3).
7. Запустить и открыть `/api/health` — там должно быть `"ecash":"ok"`.

Схему базы создавать руками не нужно: сервер накатывает миграции сам при
старте, до приёма трафика. Проверено на пустой базе — поднимается 9 таблиц.

---

## 2. Проверка после запуска

```bash
curl https://ваш-домен/api/health
```

| Ответ | Что означает | Что делать |
|---|---|---|
| `{"ok":true,"db":"up","ecash":"ok"}` | всё в порядке | — |
| `"ecash":"bad-credentials"` | ядро отвергло пару ключей | проверить `ECASH_CLIENT_ID` / `SECRET` |
| `"ecash":"unreachable"` | не достучались до контура | проверить `ECASH_API_BASE_URL` и сеть |
| `"db":"down"`, код 503 | недоступен PostgreSQL | проверить `DATABASE_URL` |

**`ok` намеренно не зависит от Ecash.** Сбой чужого апстрима не должен
перезапускать контейнер по кругу: лендинг, новости и документы работают и
без него. Состояние Ecash отдаётся отдельным полем.

При старте сервер один раз проверяет связь с ядром и пишет результат в лог.
При успехе — одна строка; при неверных ключах — заметная рамка с адресом,
причиной и перечнем того, что перестанет работать. Смотрите первые строки
лога после запуска.

## 3. Сборка образа

`NEXT_PUBLIC_*` подставляются в клиентский бандл **во время сборки**. Задать
их переменными окружения в рантайме невозможно — образ останется собранным
со старыми значениями.

```bash
docker build \
  --build-arg NEXT_PUBLIC_SITE_URL=https://ваш-домен \
  --build-arg NEXT_PUBLIC_DGIS_API_KEY=ключ_если_есть \
  -t ecash-web .
```

Без `NEXT_PUBLIC_SITE_URL` в `sitemap.xml`, `robots.txt`, `canonical` и
`hreflang` попадёт `https://ecash.kz` — молча, без единой ошибки.

Запуск (порт берётся из `$PORT`, healthcheck подхватывает его же):

```bash
docker run -d -p 8080:8080 \
  -e PORT=8080 \
  -e NODE_ENV=production \
  -e ECASH_API_BASE_URL=https://боевой-адрес \
  -e ECASH_CLIENT_ID=... \
  -e ECASH_CLIENT_SECRET=... \
  -e SESSION_SECRET=... \
  -e DATABASE_URL=postgres://... \
  -e APP_ORIGIN=https://ваш-домен \
  -e ADMIN_PHONES="+7 700 000 00 00" \
  ecash-web
```

Образ работает от непривилегированного пользователя, тома не требует.

## 4. Переменные окружения

| Переменная | Обяз. | Без неё |
|---|---|---|
| `ECASH_API_BASE_URL` | да | сервер стартует, но курсы, отделения, вход, бронь и франшиза не работают; в логе рамка с предупреждением |
| `ECASH_CLIENT_ID`, `ECASH_CLIENT_SECRET` | да | то же |
| `SESSION_SECRET` | да | **сервер не стартует** |
| `DATABASE_URL` | да | **сервер не стартует**; при недоступной базе позже — 503 на `/api/health` |
| `APP_ORIGIN` | да | **сервер не стартует**; в проде обязателен `https` |
| `ADMIN_PHONES` | нет | раздел `/admin` отдаёт 404 всем — самый частый первый вопрос |
| `NEXT_PUBLIC_SITE_URL` | нет | в SEO-разметку уходит `ecash.kz` |
| `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` | нет | push выключены, карточка подписки не показывается |
| `NEXT_PUBLIC_DGIS_API_KEY` | нет | карта работает на Яндексе, недоступна пилюля «2GIS» |
| `DGIS_SUGGEST_API_KEY` | нет | поле адреса не показывает подсказок |
| `TRANSLATE_EMAIL` | нет | автоперевод новостей на квоте 5 000 знаков в сутки вместо 50 000 |
| `HIDDEN_DEP_IDS` | нет | на боевом контуре не нужна (раздел 6) |
| `REALTIME_ENABLED` | нет | по умолчанию `true`; `false` отключает SignalR, интерфейс переходит на опрос |
| `SESSION_SECRET_PREVIOUS` | нет | заполняется только на время ротации ключа сессии |

**Приоритет:** переменная окружения > `.env.local` > `.env`. Это касается и
консольных команд (`db:migrate`, `db:seed`) — они читают те же файлы, но
переменная окружения всегда побеждает.

## 5. Что нужно знать заранее

**Права администратора — по номеру телефона.** Ролей в Ecash Mobile API нет,
своих пользователей мы не заводим. Админ тот, чей номер указан в
`ADMIN_PHONES`; номер берётся из живого ответа `/mobile/account/me` и
сверяется на **каждом** запросе к админскому API. Удаление номера закрывает
доступ немедленно, перелогин не нужен. Пусто = админов нет. Сравнение идёт
по последним 10 цифрам, формат записи любой.

**Свежая база = пустые новости.** `db:seed` в прод не попадает: образ
копирует только `drizzle/`, а `tsx` — devDependency. `/news` будет пустым,
пока статьи не заведут через `/admin`. Проверено на контейнере: страница
отдаёт 200 и корректное пустое состояние, не ошибку.

**График курса заполнится не сразу.** История копится в `rate_snapshots`
раз в 15 минут собственным снапшоттером. Первые дни вкладки «Месяц» и «Год»
будут почти плоскими — засеять их нечем.

**Загруженные картинки лежат в базе,** а не на диске: том контейнеру не
нужен, при перезапуске ничего не теряется, работает при нескольких репликах.

**Ошибка миграции не роняет старт.** Сервер логирует её и продолжает —
намеренно, чтобы сбой базы не блокировал раздачу статики. Полу-накатанный
контейнер при этом отвечает «здоров», поэтому после первого деплоя стоит
проверить лог на строки о миграциях.

**Один экземпляр приложения.** Ограничение частоты запросов, реестр SignalR,
кэши апстрима и снапшоттер курсов живут в памяти процесса. На одной реплике
всё корректно. При горизонтальном масштабировании снапшоттер начнёт писать
историю дважды — его нужно вынести в отдельный воркер.

## 6. Особенности, связанные с контуром

**`HIDDEN_DEP_IDS` — только для дев-контура.** В `api-dev.quiq.kz` рядом с
настоящими отделениями лежат служебные записи: «DEVTEST», «проверка
лимитов», «Франшизы», «ТестТест». Отличить их по данным нельзя — у них есть
и адрес, и курсы, — поэтому список скрываемых id задаётся вручную. На боевом
контуре таких записей нет: оставьте переменную пустой.

**Никаких предположений о конкретных id в коде нет.** Отделение по умолчанию
выбирается из живого списка: ближайшее к адресу пользователя, иначе первое,
у которого **реально есть курсы**. Отделение без статистики (в дев-контуре
такое есть — Onemotion отдаёт `STATISTICS_NOT_FOUND`) автоматически
пропускается при выборе по умолчанию. Явно выбранное отделение не
подменяется: если человек выбрал конкретную кассу, а курсов там нет, он
получит честное сообщение, а не чужие курсы.

**Список валют открытый.** Незнакомый код проходит насквозь и не ломает
типизацию: если на боевом контуре валют больше, они появятся сами.

## 7. Push-уведомления: что нужно на вашей стороне

Уведомления о достижении курса приходят в браузер даже с закрытой вкладкой.
Со стороны кода всё готово; заработают они при четырёх условиях, и три из
них — про инфраструктуру.

**1. HTTPS обязателен.** Web Push работает только в защищённом контексте.
Домен с валидным сертификатом — иначе браузер не даст даже подписаться.
Исключение только для `localhost` при разработке.

**2. Пара `VAPID_*`.** Сгенерируйте свою: `npx web-push generate-vapid-keys`,
положите обе половины в переменные окружения. Без них push просто выключен —
карточка подписки не показывается, остальной сайт работает как обычно.
**Менять пару после запуска нельзя**: подписки браузеров привязаны к
прежнему публичному ключу и перестанут приниматься.

**3. Исходящий HTTPS с вашего сервера.** Уведомление отправляет сервер, а не
браузер, — напрямую в службу доставки того браузера, где человек подписался:

| Браузер | Куда уходит запрос |
|---|---|
| Chrome, Edge | `fcm.googleapis.com` |
| Firefox | `*.push.services.mozilla.com` |
| Safari | `web.push.apple.com` |

Если сервер закрыт от внешней сети, отправка будет молча не доходить.
Проверить просто: в логе появится `[push] отправка не удалась` с кодом.

**4. Служебный воркер отдаётся с корня.** `/sw.js` лежит в `public/` и
попадает в образ автоматически. CSP его уже разрешает
(`worker-src 'self' blob:`, рядом `child-src` — Safari не понимает первую
директиву и откатывается на вторую).

**Ограничение Apple, не наше.** На iPhone push работает только если сайт
добавлен на домашний экран («Поделиться» → «На экран Домой»). В обычной
вкладке Safari карточка подписки не покажется — это политика Apple.

Мёртвые подписки (человек отозвал разрешение, удалил браузер) отсеиваются
сами: на ответ 404/410 запись удаляется, в логе появляется
`[push] удалено мёртвых подписок`.

## 8. Поддержка браузеров

Таргет сборки — `chrome/edge/firefox >= 111`, `safari/ios_saf >= 15.4`
(`browserslist` в `package.json`, там же обоснование).

**JS транспилируется до Safari 15.4.** Это не формальность: раньше таргет
был выше, и на iOS 15–16.3 чанк `intl-messageformat` падал с SyntaxError при
разборе — страница рисовалась через SSR, но ни одна кнопка не работала.
**Границу поднимать нельзя**, иначе эти версии сломаются полностью.

**CSS ниже Safari 16.4 / Firefox 128 работает, но не побайтово одинаково.**
Tailwind v4 официально требует именно эти версии и использует `@property`.
Проверено, что опасного нет:

| Возможность | Состояние |
|---|---|
| `color-mix()` (24 в сборке) | целиком внутри `@supports` |
| `color-mix()` в наших утилитах | сборщик разрешает в статический цвет |
| `lab()` | идёт с hex-фолбэком перед ним |
| `inset-inline`, `dvh` | в таргет попадают |
| `:has()` | **единственная деградация**: в Firefox 111–120 у поля суммы не появляется брендовая рамка; подсветка заливки от `focus-within` остаётся |

Синтаксиса, падающего при разборе, в собранном JS нет: проверены class
static blocks, regex lookbehind, приватные поля классов, логические
присваивания.

## 9. Известный дефект на стороне Ecash

**Сброс пароля отвечает успехом, но новый пароль не пускает на вход.**
Воспроизведено на логах дев-контура 12.08.2026:

```
POST /mobile/otp/send            200
POST /mobile/otp/reset-password  200   тело: true
POST /mobile/auth/login          401   INVALID_CREDENTIALS
```

Наш слой ни телефон, ни пароль не преобразует: в ядро уходит ровно то, что
ввёл человек, а номер приводится к одному виду в обоих запросах. Проверено
также, что ядро валидирует пароль раньше кода (на коротком отдаёт
`WEAK_PASSWORD`), то есть слабый пароль дал бы явную ошибку.

Обход для пользователя — вход по SMS-коду: он пароль не использует.

Просьба проверить на своей стороне.

## 10. Проверка кода

```bash
npm run typecheck
npm run lint
npm run test        # 240 модульных тестов
npm run build
npm run test:e2e    # playwright, против запущенного npm run dev
```

Секретов не требует: сборка идёт на заглушках, внешние вызовы при сборке не
выполняются.

## 11. Внешние сервисы, кроме Ecash

| Сервис | Зачем | Ключ |
|---|---|---|
| Яндекс.Карты 2.1 | карта отделений | не нужен |
| 2GIS MapGL | альтернативный движок карты | `NEXT_PUBLIC_DGIS_API_KEY` |
| 2GIS Suggest | подсказки адреса | `DGIS_SUGGEST_API_KEY` |
| OSM Nominatim | координаты по адресу | не нужен |
| Нацбанк РК (RSS) | биржевой курс для сравнения | не нужен |
| MyMemory | автоперевод новостей | `TRANSLATE_EMAIL` (необязателен) |
| Web Push | уведомления о курсе | пара `VAPID_*` |

Все подключены с мягкой деградацией: недоступность любого не роняет
страницу, пропадает только соответствующий элемент.

**Пару VAPID нельзя менять после запуска** — подписки браузеров привязаны к
прежнему публичному ключу и перестанут приниматься.

## Что именно было проверено

Собран образ с `--build-arg NEXT_PUBLIC_SITE_URL=https://ecash-partner.example`
и запущен контейнером на **нестандартном порту 8080** против **пустой базы**:

| Проверка | Результат |
|---|---|
| Миграции при старте | 9 таблиц создано сервером самостоятельно |
| Healthcheck на своём порту | `{"ok":true,"db":"up","ecash":"ok"}` |
| Проверка ключей при старте | строка в логе с адресом и clientId |
| 10 публичных страниц | все `200` |
| Кабинет и админка гостю | `307` / `401` |
| Курсы | 19, отделение выбрано автоматически (`depId 10`) |
| Отделения | список получен |
| Новости на пустой базе | `0`, корректное пустое состояние |
| `sitemap.xml`, `canonical`, `robots.txt` | домен партнёра, `ecash.kz` не осталось |

Отдельно проверено поведение при **неверных ключах**: сервер поднимается,
`/api/health` отдаёт `"ecash":"bad-credentials"`, в логе рамка с причиной,
публичные страницы продолжают работать.
