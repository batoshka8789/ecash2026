# Передача проекта

Документ для команды, которая принимает код и разворачивает его на своём
контуре. Всё остальное — в `README.md`, полный список переменных с
пояснениями — в `.env.example`.

---

## Коротко: что нужно сделать

1. Получить боевую пару `ECASH_CLIENT_ID` / `ECASH_CLIENT_SECRET`
   (dev-пара из документации на проде не работает).
2. Поставить `ECASH_API_BASE_URL` на боевой адрес.
3. Сгенерировать `SESSION_SECRET` — `openssl rand -base64 32`.
4. Указать `DATABASE_URL` и `APP_ORIGIN` (в проде обязателен `https`).
5. Заполнить `ADMIN_PHONES` — иначе раздел `/admin` закрыт для всех.
6. Собрать образ, **передав `NEXT_PUBLIC_*` build-аргументами** (см. ниже).
7. Открыть `/api/health` и убедиться, что там `"ecash":"ok"`.

Шаг 7 — главный: он отвечает на вопрос «ключи приняты?» одним запросом.

---

## Проверка после переключения

```bash
curl https://ваш-домен/api/health
```

| Ответ | Что означает |
|---|---|
| `{"ok":true,"db":"up","ecash":"ok"}` | всё в порядке |
| `"ecash":"bad-credentials"` | пара `ECASH_CLIENT_ID`/`SECRET` отвергнута ядром |
| `"ecash":"unreachable"` | не достучались до `ECASH_API_BASE_URL` |
| `"db":"down"`, код 503 | недоступен Postgres |

`ok` намеренно **не зависит** от Ecash: сбой чужого апстрима не должен
перезапускать контейнер по кругу. Лендинг, новости и документы работают
и без него.

При старте сервер один раз проверяет связь с Ecash и пишет результат в лог —
при неверных ключах это заметная рамка с перечнем того, что перестанет
работать. Смотрите первые строки лога после запуска.

## `NEXT_PUBLIC_*` — только на сборке

Next подставляет эти значения в клиентский бандл **во время сборки**.
Задать их переменными окружения в рантайме невозможно — образ будет собран
с прежними значениями.

```bash
docker build \
  --build-arg NEXT_PUBLIC_SITE_URL=https://ваш-домен \
  --build-arg NEXT_PUBLIC_DGIS_API_KEY=... \
  -t ecash-web .
```

Без `NEXT_PUBLIC_SITE_URL` в `sitemap.xml`, `robots.txt`, canonical и
hreflang попадёт `https://ecash.kz` — молча, без единой ошибки.

## Что ломается без каждого ключа

| Переменная | Обязательна | Без неё |
|---|---|---|
| `ECASH_API_BASE_URL`, `ECASH_CLIENT_ID`, `ECASH_CLIENT_SECRET` | да | сервер стартует, но курсы, отделения, вход, бронь и франшиза не работают; в логе рамка с предупреждением |
| `SESSION_SECRET` | да | сервер не стартует (валидация окружения) |
| `DATABASE_URL` | да | сервер не стартует; при недоступной базе позже — 503 на `/api/health` |
| `APP_ORIGIN` | да | сервер не стартует; в проде обязателен `https` |
| `ADMIN_PHONES` | нет | раздел `/admin` отдаёт 404 всем — самый частый первый вопрос |
| `NEXT_PUBLIC_SITE_URL` | нет | в SEO-разметку уходит `ecash.kz` |
| `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` | нет | push-уведомления выключены, карточка подписки не показывается |
| `NEXT_PUBLIC_DGIS_API_KEY` | нет | карта работает на Яндексе, недоступна только пилюля «2GIS» |
| `DGIS_SUGGEST_API_KEY` | нет | поле адреса не показывает подсказок |
| `TRANSLATE_EMAIL` | нет | автоперевод новостей на квоте 5 000 знаков в сутки вместо 50 000 |
| `HIDDEN_DEP_IDS` | нет | на боевом контуре не нужна (см. ниже) |

## Что нужно знать заранее

**Права администратора — по номеру телефона.** Ролей в Ecash Mobile API нет,
своих пользователей мы не заводим. Админ тот, чей номер указан в
`ADMIN_PHONES`; номер берётся из живого ответа `/mobile/account/me` и
сверяется на **каждом** запросе к админскому API. Удаление номера из списка
закрывает доступ немедленно. Пусто = админов нет.

**Пару VAPID нельзя менять после запуска.** Подписки браузеров привязаны к
прежнему публичному ключу и перестанут приниматься.

**Свежая база = пустые новости.** `db:seed` в прод не попадает: образ
копирует только `drizzle/`, а `tsx` — devDependency. `/news` будет пустым,
пока статьи не заведут через `/admin`. График курса будет почти плоским
несколько недель: история копится в `rate_snapshots` раз в 15 минут и
засеяться не может.

**Ошибка миграции не роняет старт.** Сервер логирует её и продолжает —
намеренно, чтобы сбой БД не блокировал раздачу статики. Полу-накатанный
контейнер отвечает «здоров» и падает на записи, поэтому после первого
деплоя стоит проверить лог на строки о миграциях.

**Один экземпляр приложения.** Rate-limit, реестр SignalR, кэши апстрима и
снапшоттер курсов живут в памяти процесса. На одной реплике всё корректно;
при горизонтальном масштабировании снапшоттер начнёт писать историю дважды —
его нужно вынести в отдельный воркер.

**`HIDDEN_DEP_IDS` — только для дев-контура.** В `api-dev.quiq.kz` рядом с
настоящими отделениями лежат служебные записи («DEVTEST», «проверка
лимитов», «Франшизы»). Отличить их по данным нельзя — у них есть и адрес, и
курсы, — поэтому список задаётся вручную. На боевом контуре таких записей
нет: оставьте переменную пустой.

**Никаких предположений о конкретных id в коде нет.** Отделение по умолчанию
берётся из живого списка (ближайшее к адресу пользователя, иначе первое в
списке). Список валют — открытый: незнакомый код проходит насквозь и не
ломает типизацию.

## Поддержка браузеров

Таргет сборки — `chrome/edge/firefox >= 111`, `safari/ios_saf >= 15.4`
(`browserslist` в `package.json`, там же обоснование).

**JS транспилируется до Safari 15.4.** Это не формальность: раньше таргет
был выше, и на iOS 15–16.3 чанк `intl-messageformat` падал с SyntaxError
при разборе — страница рисовалась через SSR, но ни одна кнопка не работала.
Границу поднимать нельзя, иначе эти версии сломаются полностью.

**CSS ниже Safari 16.4 / Firefox 128 работает, но не побайтово одинаково.**
Tailwind v4 официально требует именно эти версии и использует `@property`
(67 объявлений в сборке); ниже — переменные `--tw-*` становятся
наследуемыми. Проверено, что опасного нет:

| Возможность | Состояние |
|---|---|
| `color-mix()` (24 в сборке) | целиком внутри `@supports` — на старых просто не применяется |
| `color-mix()` в наших утилитах | сборщик разрешает в статический цвет (`#2626269e`) |
| `lab()` | идёт с hex-фолбэком перед ним |
| `inset-inline` | Safari 14.1+, Firefox 63+ — в таргет попадает |
| `dvh` | Safari 15.4+, Firefox 101+ — в таргет попадает |
| `:has()` | **единственная деградация**: в Firefox 111–120 у поля суммы не появляется брендовая рамка, подсветка заливки от `focus-within` остаётся |

Синтаксиса, падающего при разборе, в собранном JS нет: проверены class
static blocks, regex lookbehind, приватные поля классов и логические
присваивания.

## Известный дефект на стороне Ecash

**Сброс пароля отвечает успехом, но новый пароль не пускает на вход.**
Воспроизведено на логах дев-контура 12.08.2026:

```
POST /mobile/otp/send            200
POST /mobile/otp/reset-password  200   тело: true
POST /mobile/auth/login          401   INVALID_CREDENTIALS
```

Наш слой ни телефон, ни пароль не преобразует: в ядро уходит ровно то, что
ввёл человек, а номер приводится к одному виду в обоих запросах. Обход для
пользователя — вход по SMS-коду, он пароль не использует.

Просьба проверить на своей стороне.

## Проверка кода

```bash
npm run typecheck
npm run lint
npm run test        # 240 модульных тестов
npm run build
npm run test:e2e    # против запущенного npm run dev
```

CI (`.github/workflows/ci.yml`) прогоняет первые четыре на каждый push и PR.
Секретов не требует — сборка идёт на заглушках, внешние вызовы при сборке не
выполняются.

## Внешние сервисы, кроме Ecash

| Сервис | Зачем | Ключ |
|---|---|---|
| Яндекс.Карты 2.1 | карта отделений | не нужен |
| 2GIS MapGL | альтернативный движок карты | `NEXT_PUBLIC_DGIS_API_KEY` |
| 2GIS Suggest | подсказки адреса | `DGIS_SUGGEST_API_KEY` |
| OSM Nominatim | координаты по адресу | не нужен |
| Нацбанк РК (RSS) | биржевой курс для сравнения | не нужен |
| MyMemory | автоперевод новостей | `TRANSLATE_EMAIL` (необязателен) |

Все подключены с мягкой деградацией: недоступность любого из них не роняет
страницу, пропадает только соответствующий элемент.
