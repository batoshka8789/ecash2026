# ecash

Фронтенд сервиса обмена валют, интегрированный с реальным API Ecash Mobile
(`api-dev.quiq.kz`): курсы и отделения вживую, бронирование курса на 60 минут,
индивидуальный курс с подтверждением казначея, личный кабинет, подписки на курс.
Свёрстан по макету Figma, мультиязычный (ru / en / kk), тёмная и светлая темы.

## Стек

- **Next.js 16** (App Router, Turbopack) + **React 19** + TypeScript strict
- **Tailwind CSS v4** — токены из макета в `src/app/tokens.css`
- **next-intl** — локали ru / en / kk, `/` без префикса, `/en`, `/kk`
- **TanStack Query v5** — кэш данных, оптимистичные обновления, ретраи
- **PostgreSQL + Drizzle** — наш слой: анкета, избранное, подписки, новости,
  накопление истории курсов
- **SignalR → SSE** — события брони от Ecash в браузер без прямого доступа
- **MapLibre GL + OSM** — интерактивная карта отделений без ключей

## Архитектура

Браузер ходит только в наш BFF (`/api/*`). Наружу смотрит только сервер:

```
браузер ──► /api/* (route handlers: zod, rate-limit, same-origin)
              ├──► src/server/ecash/*    → api-dev.quiq.kz  (Bearer-токены)
              ├──► src/server/db/*       → PostgreSQL (Drizzle)
              └──► src/server/realtime/* → SignalR /appHub ──► SSE
```

### Можно ли обращаться к api-dev.quiq.kz напрямую из браузера

Технически — да. Замер CORS-заголовков апстрима (29.07.2026):

| Origin | `Access-Control-Allow-Origin` в ответе |
| --- | --- |
| `https://ecash.kz` | есть |
| `http://localhost:3000` | есть |
| `http://localhost:3100`, `:3200`, `:5173` | нет |
| `https://localhost:3000`, `http://127.0.0.1:3000` | нет |

Белый список привязан к origin целиком — порт, схема и хост считаются
буквально. Для разрешённого origin preflight отдаёт
`Access-Control-Allow-Credentials: true`, `Allow-Headers: authorization,
content-type`, `Allow-Methods: GET|POST`, то есть из браузера доступны и
справочники, и бронь. Проверено вживую: со страницы на `localhost:3000`
браузер получает сервисный токен и читает `/Department/depListApp` сам.

Поэтому схема гибридная — см. `src/lib/ecash-direct.ts`:

```
браузер ──► api-dev.quiq.kz          depListApp · depInfo · best-rate
       └──► /api/* (наш сервер) ──► всё остальное
```

**Напрямую** идут публичные справочники: список отделений, карточка
отделения, лучший курс. Мапперы у них общие с сервером — вынесены в
`src/shared/ecash/` (чистые функции, без доступа к окружению).

**Через свой сервер** остаётся то, что напрямую взять нельзя:

1. **clientSecret не покидает сервер.** Сервисный токен выдаётся по паре
   `clientId` + `clientSecret`, и положить секрет в JS нельзя — его прочитает
   любой из devtools и начнёт выпускать токены от имени приложения. Браузер
   берёт у нас готовый токен (`GET /api/ecash-token`): он живёт час и по
   редакции 3 открывает ровно публичные справочники. В клиентские бандлы ни
   секрет, ни `ecash.app.token` не попадают — серверные модули помечены
   `import 'server-only'`.
2. **Токен пользователя** живёт в зашифрованной (AES-256-GCM) httpOnly-куке и
   недоступен из JS — защита от XSS. Поэтому вход, бронь, кабинет и операции
   ходят через BFF.
3. **Составные ответы.** `/api/rates` — не проксирование, а склейка курсов
   Ecash с курсом НБ РК, избранным и конкурентами из нашей БД. Туда же
   новости, подписки и история курсов для графика.

Два условия, без которых прямые вызовы молча ломаются:

- **origin ровно из белого списка.** В деве это `http://localhost:3000` —
  поэтому порт в `.claude/launch.json` жёстко 3000, а не любой свободный.
- **`connect-src` в CSP.** Свой же CSP рубит запрос раньше сети, и в консоли
  видно `Failed to fetch`, неотличимое от CORS-отказа. Origin апстрима
  подставляется в заголовок из `ECASH_API_BASE_URL` (`next.config.ts`).

## Запуск

```bash
npm install
docker compose up -d db     # PostgreSQL 17
npm run db:migrate          # миграции
npm run db:seed             # новости и конкуренты
npm run dev
```

Откроется `http://localhost:3000` (порт настраивается в `.claude/launch.json`).

Обязательные переменные окружения — см. `.env.example`. Без валидного
окружения сервер не стартует (проверка в `src/instrumentation.ts`).

### Демо-режим

`ECASH_OTP_MOCK=1` (только dev; в продакшене сборка с ним падает):

- вход: любой телефон + пароль `ecash2026`, либо SMS-код `000000`
- тестовый аккаунт для проверки формы: логин `+7 (700) 000 00 01`,
  пароль `ecash2026` (аккаунт заводится на лету по введённому номеру,
  `accountId = demo-77000000001`, привязан к клиенту 5512)
- «казначей»-симулятор подтверждает бронь через ~8 секунд,
  для индивидуального курса предлагает курс и ждёт решения
- реальные SMS не отправляются

С реальным аккаунтом Ecash всё работает без флага: SMS уходят через
шлюз Ecash, заявки обрабатывает настоящий казначей.

## Структура

```
src/
  app/[locale]/          страницы: лендинг, приложение, кабинет, заявки
  app/api/               BFF: departments, rates, auth+otp, requests,
                         profile, favorites, rate-alerts, news, events(SSE)
  server/
    ecash/               клиент upstream: http, ошибки (2 формы), токены,
                         мапперы (своп lat/lon, строки→числа), курс НБ РК
    db/                  Drizzle: схема, клиент, сид
    realtime/            SignalR-релей с подпиской на аккаунт
    demo/                демо-казначей (только ECASH_OTP_MOCK=1)
    api/                 respond/guard: единый формат ответов, периметр
    jobs/                снапшоттер курсов (история для графика)
  shared/schemas.ts      zod-схемы — общие для клиента и сервера
  lib/                   api-клиент, TanStack-провайдер, серверное время,
                         форматирование, доменные типы
  components/            landing / sections / flows / profile / requests /
                         auth / layout / ui
  i18n/                  маршрутизация локалей
messages/                тексты ru / en / kk (в синхроне, ~500 ключей)
drizzle/                 миграции
design/                  карта экранов макета и инвентарь
scripts/                 выгрузка макета из Figma и извлечение спек
```

## Бизнес-процесс брони (по документации Ecash, редакция 3)

1. `POST /api/requests` → заявка в статусе **0 «Введен»**, ответ мгновенный.
2. Казначей отвечает (событие по SSE или поллинг):
   подтвердил → статус **8 «Забронирована»**, бронь на 60 минут
   **с момента его ответа**; отказал → статус **3 «Отмена»**.
3. Клиент приходит в отделение → кассир проводит → статус **1 «Проведена»**
   с талоном; либо отмена/истечение срока → статус 3.

Индивидуальный курс: заявка с `isIndividual`, казначей предлагает курс,
у клиента 60 минут на «Согласен / Отказываюсь», дальше — обычная бронь.

Таймеры считаются от серверного времени (`X-Server-Time` в каждом ответе
BFF) — сбитые часы клиента не ломают отсчёт.

## Продакшен

```bash
docker compose --profile prod up --build
```

`Dockerfile` собирает standalone-бандл, контейнер с healthcheck
(`/api/health`), заголовки безопасности (CSP, HSTS, …) — в `next.config.ts`.
Перед выкладкой: выпустить прод-пару `ECASH_CLIENT_ID/SECRET` у команды
Ecash (dev-пара из документации в проде не работает и должна быть
ротирована), сгенерировать `SESSION_SECRET`, выключить `ECASH_OTP_MOCK`.

## Работа с макетом

Скрипты в `scripts/` тянут дерево макета через Figma REST API и извлекают
точные спеки: геометрия, автолэйауты, заливки, типографика.

```bash
npm run figma:structure          # инвентарь страниц и фреймов
npm run spec -- 1279:104497      # спека узла
npm run spec -- <id> --text      # тексты со стилями
```

Нужны `FIGMA_TOKEN` и `FIGMA_FILE_KEY` в `.env.local` (не для запуска
приложения — только для этих скриптов).
