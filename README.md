# ecash

Фронтенд сервиса обмена валют, интегрированный с реальным API Ecash Mobile
(`api-dev.quiq.kz`): курсы и отделения вживую, бронирование курса на 60 минут,
индивидуальный курс с подтверждением казначея, личный кабинет, подписки на курс.
Свёрстан по макету Figma, мультиязычный (ru / en / kk / zh), тёмная и светлая темы.

> **Принимаете проект?** Начните с [HANDOFF.md](HANDOFF.md): что заменить,
> как проверить, что ключи приняты, и какие подводные камни известны заранее.

## Стек

- **Next.js 16** (App Router, Turbopack) + **React 19** + TypeScript strict
- **Tailwind CSS v4** — токены из макета в `src/app/tokens.css`
- **next-intl** — локали ru / en / kk / zh, `/` без префикса, `/en`, `/kk`, `/zh`
- **TanStack Query v5** — кэш данных, оптимистичные обновления, ретраи
- **PostgreSQL + Drizzle** — наш слой: анкета, избранное, подписки, новости,
  накопление истории курсов
- **SignalR → SSE** — события брони от Ecash в браузер без прямого доступа
- **2GIS MapGL + Яндекс.Карты** — карта отделений с переключением движка;
  без ключа 2GIS работает на Яндексе, которому ключ не нужен

## Архитектура

Браузер ходит только в наш BFF (`/api/*`). Наружу смотрит только сервер:

```
браузер ──► /api/* (route handlers: zod, rate-limit, same-origin)
              ├──► src/server/ecash/*    → api-dev.quiq.kz  (Bearer-токены)
              ├──► src/server/db/*       → PostgreSQL (Drizzle)
              └──► src/server/realtime/* → SignalR /appHub ──► SSE
```

### Почему браузер не ходит в api-dev.quiq.kz напрямую

Был период, когда публичные справочники (отделения, курсы, лучший курс)
браузер тянул из апстрима сам — CORS у него это позволял. Замер заголовков
(29.07.2026) показывает, чем это кончилось:

| Origin | `Access-Control-Allow-Origin` в ответе |
| --- | --- |
| `https://ecash.kz` | есть |
| `http://localhost:3000` | есть |
| всё остальное — включая `*.up.railway.app` | нет |

Белый список привязан к origin буквально: хост, схема и порт. То есть прямые
вызовы работали ровно на двух адресах, а на любом новом домене — стенде,
превью-деплое, своём порту в деве — preflight отвечал без
`Access-Control-Allow-Origin`, и отделения с курсами просто исчезали с экрана.
Так и произошло на Railway.

Свой белый список у чужого API мы не контролируем, поэтому справочники
забираются на сервере, где CORS не действует вообще:

```
браузер ──► /api/* (наш сервер) ──► api-dev.quiq.kz
```

Побочные плюсы: сервисный токен больше не выдаётся в браузер (ручки
`/api/ecash-token` не стало), апстрим убран из `connect-src` в CSP, а порт
дев-сервера снова любой.

Через свой сервер идёт всё, и часть данных иначе получить нельзя:

1. **clientSecret не покидает сервер.** Сервисный токен выдаётся по паре
   `clientId` + `clientSecret`; в клиентские бандлы ни секрет, ни
   `ecash.app.token` не попадают — серверные модули помечены
   `import 'server-only'`.
2. **Токен пользователя** живёт в зашифрованной (AES-256-GCM) httpOnly-куке и
   недоступен из JS — защита от XSS.
3. **Составные ответы.** `/api/rates` — не проксирование, а склейка курсов
   Ecash с курсом НБ РК, избранным и конкурентами из нашей БД. Курсы Ecash там
   единственная обязательная часть: если Postgres или nationalbank.kz
   недоступны, экран курсов всё равно открывается.

## Запуск

Нужен **Node 22** (версия зафиксирована в `Dockerfile` и CI).

```bash
cp .env.example .env.local  # и заполнить — см. ниже
npm install
docker compose up -d db     # PostgreSQL 17
npm run db:migrate          # миграции
npm run db:seed             # новости и конкуренты
npm run dev
```

Откроется `http://localhost:3000` (другой порт — `next dev -p <порт>`).

**Про env-файл.** Приложение читает `.env.local`, консольные инструменты
(`db:migrate`, `db:seed`) — тоже: они грузят `.env`, затем `.env.local`
поверх. Без `DATABASE_URL` команды падают с явным сообщением, а не уходят
молча на localhost.

В `.env.example` **пустые** `ECASH_CLIENT_SECRET` и `SESSION_SECRET` —
сервер без них не стартует (валидация окружения в `src/instrumentation.ts`).
Секрет сессии генерируется командой `openssl rand -base64 32`.

### Авторизация

Вход и регистрация идут только через ядро Ecash: SMS-коды отправляет шлюз
Ecash, заявки обрабатывает настоящий казначей. Отдельного тестового входа
в приложении нет — для проверки сценариев нужен реальный аккаунт Ecash.

Доступ к разделу `/admin` привязан к **номеру телефона**: админ тот и только
тот, чей номер перечислен в `ADMIN_PHONES`. Отдельных паролей нет — человек
входит обычным образом через Ecash, а номер берётся из живого ответа
`/mobile/account/me` и сверяется со списком на **каждом** запросе к
админскому API. Право нигде не хранится, поэтому удаление номера из списка
закрывает доступ сразу, не дожидаясь истечения сессии.

Ролей в Ecash Mobile API нет, своих пользователей мы не заводим — номер и
есть признак админа.

## Структура

```
src/
  app/[locale]/          страницы: лендинг, приложение, кабинет, заявки
  app/api/               BFF: departments, rates, auth+otp, requests,
                         profile, favorites, rate-alerts, news, events(SSE)
  server/
    ecash/               клиент upstream: http, ошибки (2 формы), токены,
                         мапперы (своп lat/lon, строки→числа), курс НБ РК
    db/                  Drizzle: схема, клиент, сид
    realtime/            SignalR-релей с подпиской на аккаунт
    api/                 respond/guard: единый формат ответов, периметр
    jobs/                снапшоттер курсов (история графика) и наблюдатель
                         заявок (push о решении казначея)
  shared/schemas.ts      zod-схемы — общие для клиента и сервера
  lib/                   api-клиент, TanStack-провайдер, серверное время,
                         форматирование, доменные типы
  components/            landing / sections / flows / profile / requests /
                         auth / layout / ui
  i18n/                  маршрутизация локалей
messages/                тексты ru / en / kk / zh (наборы ключей в синхроне)
drizzle/                 миграции
design/                  карта экранов макета и инвентарь
scripts/                 выгрузка макета из Figma и извлечение спек
```

## Бизнес-процесс брони (по документации Ecash, редакция 3)

1. `POST /api/requests` → заявка в статусе **0 «Введен»**, ответ мгновенный.
2. Казначей отвечает (событие по SSE или поллинг):
   подтвердил → статус **8 «Забронирована»**, бронь на 60 минут
   **с момента его ответа**; отказал → статус **3 «Отмена»**.
3. Клиент приходит в отделение → кассир проводит → статус **1 «Проведена»**
   с талоном; либо отмена/истечение срока → статус 3.

Индивидуальный курс: заявка с `isIndividual`, казначей предлагает курс,
у клиента 60 минут на «Согласен / Отказываюсь», дальше — обычная бронь.

Таймеры считаются от серверного времени (`X-Server-Time` в каждом ответе
BFF) — сбитые часы клиента не ломают отсчёт.

## Уведомления

Push двух видов, оба доходят даже с закрытой вкладкой (`server/push.ts`,
служебный воркер — `public/sw.js`; включаются парой `VAPID_*`, без неё
раздел подписки просто не показывается).

**Достижение курса.** Подписка живёт в нашей БД (`rate_alerts`). Снапшоттер
(`server/jobs/snapshots.ts`, раз в 15 минут) сверяет отметку с лучшим курсом
рынка — правило в `lib/rate-alert.ts`, там же тесты: покупателю нужен
минимальный курс продажи, продавцу — максимальный курс покупки. Сработавшая
подписка получает `firedAt` и попадает в кабинет заголовком «Курс достиг
вашей отметки».

**Решение казначея.** Бронь подтверждена, предложен индивидуальный курс,
заявка отменена, обмен проведён — наблюдатель (`server/jobs/
request-watcher.ts`, раз в минуту) перечитывает активные заявки и шлёт push
на переходах статуса. Заявки Ecash читаются только пользовательским токеном,
поэтому наблюдатель работает через короткий кеш access-токена в памяти
процесса (`server/token-cache.ts`) — токены не пишутся ни в базу, ни на
диск; окно доставки ~15 минут после последнего действия человека. О
собственных действиях push не шлётся: всё, что человек сделал или увидел на
сайте, синхронизирует наблюдение (`server/request-watch.ts`, там же тесты
переходов).

## Продакшен

```bash
docker compose --profile prod up --build
```

`Dockerfile` собирает standalone-бандл, запускается от непривилегированного
пользователя, healthcheck (`/api/health`) слушает `$PORT`. Заголовки
безопасности (CSP, HSTS, …) — в `next.config.ts`.

**Перед выкладкой:**

1. Выпустить прод-пару `ECASH_CLIENT_ID/SECRET` у команды Ecash — dev-пара из
   документации в проде не работает и подлежит ротации.
2. Заменить `ECASH_API_BASE_URL` на боевой адрес.
3. Сгенерировать `SESSION_SECRET`.
4. Заполнить `ADMIN_PHONES` — иначе раздел `/admin` недоступен никому.
5. **`NEXT_PUBLIC_*` передать build-arg'ами**, а не переменными рантайма:
   Next подставляет их в клиентский бандл на сборке.

```bash
docker build \
  --build-arg NEXT_PUBLIC_SITE_URL=https://ваш-домен \
  --build-arg NEXT_PUBLIC_DGIS_API_KEY=... \
  -t ecash-web .
```

Без `NEXT_PUBLIC_SITE_URL` в `sitemap.xml`, `robots.txt`, canonical и
hreflang попадёт `https://ecash.kz` — молча, без единой ошибки.

## Работа с макетом — внутренний инструмент

> Для запуска и поддержки приложения **не нужен**. Раздел описывает, как
> сверялась вёрстка с Figma, и работает только у команды, у которой есть
> доступ к исходному файлу макета.

Скрипты в `scripts/` тянут дерево макета через Figma REST API и извлекают
точные спеки: геометрия, автолэйауты, заливки, типографика.

```bash
npm run figma:structure          # инвентарь страниц и фреймов
npm run spec -- 1279:104497      # спека узла
npm run spec -- <id> --text      # тексты со стилями
```

Нужны `FIGMA_TOKEN` и `FIGMA_FILE_KEY` в `.env.local`. Отдельно `npm run spec`
требует локальный дамп макета в `design/raw/` — он не в репозитории (300+ МБ),
поэтому без него команда сразу сообщит, что дампа нет.
